# मेरा AI साथी

A small personal chat app that accepts typed or spoken questions, answers in Hindi, and reads answers aloud. Answers are generated by Ollama on your own computer; the app does not send chat messages to a cloud AI service.

## Requirements

- Python 3.10 or newer (the backend uses only the Python standard library)
- [Ollama for Windows](https://ollama.com/download)
- Enough free disk space for the local model download (the default Qwen 2.5 3B model is a few GB)

## Free hosted web version

The optional Render Blueprint in `render.yaml` deploys a single-user web version on Render's free web-service plan and uses the Gemini Developer API free tier for chat. Free API quotas and model availability are controlled by Google and can change. Google states that content submitted on the free tier may be used to improve its products; do not send private or sensitive information through the hosted version. See [Gemini API pricing](https://ai.google.dev/gemini-api/docs/pricing) and [Gemini API terms](https://ai.google.dev/gemini-api/terms).

1. Create a Gemini API key in [Google AI Studio](https://aistudio.google.com/apikey). Keep the project on the free tier and do not enable billing if you require zero API charges. Keep the key secret.
2. In Render, create a new Blueprint from this GitHub repository. Enter `GEMINI_API_KEY` and a strong `APP_PASSWORD` (at least 14 characters) when prompted. Render generates `SESSION_SECRET`; do not commit any of these values.
3. Wait for the first deploy, then open the Render URL and sign in with `APP_PASSWORD`.

The API key stays on the server. Hosted chat is protected by a single-user password, secure session cookie, same-origin checks, and an in-memory request limit. The Render free service can sleep when idle and its local filesystem is temporary: music uploads and library entries may disappear after a restart or redeploy. The free hosted version does not run the ACE-Step song generator or store personal voice samples. Speech input/output uses the visitor's browser/device. The Windows desktop app continues to use local Ollama, Windows voices, and the local song generator.

## Run on Windows PowerShell

1. Install Ollama and download the local model once:

   ```powershell
   ollama pull qwen2.5:3b
   ```

   Ollama should be running in the background. The model download needs internet once; chats are sent only to Ollama on your own computer.

2. Start the app from this folder:

   ```powershell
   python server.py
   ```

3. Open http://localhost:3000 in Chrome or Edge and allow microphone access. Press the phone button to start a hands-free voice conversation: speak your question, and the assistant will answer aloud and listen again. Press the stop button to end the conversation.

The app reads new answers aloud and offers feminine/warm and deep/masculine delivery styles. Use **आवाज़ जाँचें** to test speech playback, **आवाज़ें खोजें** after installing a voice, and **Windows voice जोड़ें** to open Windows Speech settings. Add a Hindi speech voice in Windows language/speech settings, then return and refresh; restart the app if Windows does not publish the new voice immediately. Until Hindi is installed, Sweetheart uses an available Windows voice such as David or Zira as a fallback and clearly warns that its Hindi pronunciation may be poor. The voice selector prefers a Hindi voice when one is installed. Speech pitch and response style cannot create a new natural voice or imitate a particular person. The assistant uses light humor when appropriate and stays serious for sensitive topics. The assistant can explain general phone specifications and buying trade-offs, but it does not have live prices or product listings; check exact model variants and current offers before buying. The assistant is named Sweetheart and was developed by Piyush and Nitish. Voice recognition is provided by the browser and may be processed by its speech service; typed chat requests are sent only to the local Ollama service.

In local mode, chat messages are sent only to Ollama at `127.0.0.1:11434`; no cloud API key is used. Do not expose the local server to the public internet.

The voice-style selector also offers a general deep, confident Indian male delivery. This is a pitch/rate style applied to an installed Hindi speech voice, not a recording or imitation of any real person. A natural male Hindi voice requires a compatible Hindi voice to be installed in Windows or the browser.

The **म्यूज़िक** tab is available in both the web page and the Windows app. Add a title and artist, then optional album, genre, year, track number, language, mood, composer, lyricist, label, notes, and an audio file. Audio files up to 50 MB can be played in the library; entries can also be searched and deleted. In local mode, the web server and desktop app save the shared library under `%LOCALAPPDATA%\Sweetheart\Music` on this PC, so either version can see the same tracks. Local-mode music files and metadata stay on this PC. The web version must be running on this same PC to access the local library; do not expose its server to the public internet.

### Generate a sung song from a prompt

The Music tab can create an original sung song from a description, with a deep male, female, or duet vocal style. You can provide your own lyrics; otherwise Sweetheart asks the already-installed local Ollama model to draft original Hindi lyrics. The ACE-Step 1.5 song model then generates the audio and saves it in the same local music library, where it can be played or downloaded. It does not imitate a real singer.

On Windows, install `uv` first if it is not already available:

```powershell
powershell.exe -NoProfile -ExecutionPolicy Bypass -Command "irm https://astral.sh/uv/install.ps1 | iex"
```

Then run the one-time setup from the project folder:

```powershell
powershell.exe -NoProfile -ExecutionPolicy Bypass -File .\setup-song-generator.ps1
```

This creates an isolated Python 3.12 environment under `%LOCALAPPDATA%\Sweetheart\SongGenerator`, installs CPU-only PyTorch and ACE-Step dependencies, and downloads the official ACE-Step source. It does not change Sweetheart's existing Python environment. The song model weights (about 10 GB) download the first time you generate a song; generation on a CPU-only computer can take several minutes or longer. Sweetheart starts the model API on `127.0.0.1` only when needed. Keep Ollama running for automatic lyrics; supplying your own lyrics avoids the lyrics-drafting request.

To choose a different model already installed in Ollama, set `OLLAMA_MODEL` before starting the server. The default is `qwen2.5:3b`. You can also use `npm start` if Node.js is installed.

### Build the Windows desktop app

The desktop app opens in its own window and does not need a browser tab. It uses the Microsoft Edge WebView2 Runtime (already installed with current Edge on most Windows PCs) and connects to the Ollama service on this computer.

1. From PowerShell in the project folder, build the app:

   ```powershell
   powershell.exe -NoProfile -ExecutionPolicy Bypass -File .\build-desktop.ps1
   ```

   The first build installs the desktop packaging tools and may take a few minutes.

2. Open `dist\Sweetheart.exe`. You can pin it to Start or create a desktop shortcut. Ollama must be running for AI replies; the app does not bundle Ollama or download a model by itself.

The executable includes Sweetheart's custom heart logo. It runs locally and serves its interface only on a temporary loopback port on your own PC. The desktop executable uses Ollama and intentionally leaves the optional fine-tuning libraries out to keep the app much smaller. To use a trained adapter, launch the Python server with `.\.venv\Scripts\python.exe server.py` instead.

The speech selector offers up to three installed voices in Windows/WebView2 and prioritizes the selected style. Use the **आवाज़ जाँचें** button before chatting to verify the app can play sound. If voices do not appear, use **Windows voice जोड़ें**, install Hindi speech in Windows settings, and press **आवाज़ें खोजें**; restart the app if needed. The **अपनी voice recording जोड़ें** controls can record up to 15 seconds or save a selected audio sample locally (up to 25 MB), play it back, and delete it. This is a private sample recording, not an AI-generated voice or a voice clone. Turning a recording into a custom speaking voice would require a separate local voice-cloning model, which is not included.

### Fine-tune your own assistant

The project includes a CPU LoRA fine-tuning script for `Qwen/Qwen2.5-0.5B-Instruct`. Your computer has integrated graphics rather than a dedicated NVIDIA GPU, so the first model download and CPU training may take a while. Training downloads the base model once; chat and training then run locally without a cloud AI API.

1. Install the training packages in the project's Python environment:

   ```powershell
   .\.venv\Scripts\python.exe -m pip install -r requirements-training.txt
   ```

2. Create or edit your training dataset:

   ```powershell
   if (-not (Test-Path data\training_data.jsonl)) {
       Copy-Item data\training_data.example.jsonl data\training_data.jsonl
   }
   notepad data\training_data.jsonl
   ```

   Keep one JSON object per line, with a `question` and the answer you want, for example:

   ```json
   {"question":"फोन की battery capacity कैसे compare करूँ?","answer":"सिर्फ mAh न देखें। Processor, display, software और reviews भी battery life पर असर डालते हैं।"}
   ```

   Keep any existing `training_data.jsonl`; the command above copies the sample only if the file does not exist. The sample file contains just two format examples, so add at least 5 of your own examples; 20-50 varied, accurate examples are a better starting point. Use realistic questions and the style of answer you want. Never put passwords or other secrets in training data.

3. Start training:

   ```powershell
   .\.venv\Scripts\python.exe finetune.py --epochs 3 --learning-rate 2e-4
   ```

   Training runs on CPU and can take a long time. The first run downloads `Qwen/Qwen2.5-0.5B-Instruct` from Hugging Face; no API key is used. The LoRA adapter is written to `models/personal-hindi-lora`.

4. Start/restart the app using the same Python environment:

   ```powershell
   .\.venv\Scripts\python.exe server.py
   ```

   When the adapter exists, the app uses the fine-tuned 0.5B model locally and adds Sweetheart's Hindi and phone-help instructions to its prompt. This replaces the default Ollama `qwen2.5:3b` chat path; remove or rename the adapter folder if you want to switch back to Ollama. Fine-tuning teaches response patterns from your examples; it does not add live product data or guarantee new facts.
